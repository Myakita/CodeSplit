# Приёмка CodeSplit MVP 0.1.0

Дата: 2026-08-13. Окружение: Windows, MSVC 19.50, Ninja, CMake 4.1, LLVM/Clang 22.1.8.

## Принятый пользовательский сценарий

CodeSplit находит свободную функцию по USR, строит объяснимый план и точный dry-run. При
подтверждении прежнее тело переносится в переименованную implementation-функцию нового `.cpp`.
Исходное имя и сигнатура остаются на месте, а новое тело вызывает implementation-функцию. Новый
файл добавляется в доказанную CMake-цель.

Перед завершением транзакции обе единицы трансляции повторно анализируются настоящей compilation
command и затронутая цель собирается. Неуспех восстанавливает исходник, цель, `CMakeLists.txt` и
производный build graph. Существующие call sites и тесты не меняются; дублирующий тест CodeSplit не
создаёт.

Встроенный `examples/mvp` подтверждает полный путь для `calculate_total(int, int)`: прежний
`main.cpp` после extraction продолжает вызывать `calculate_total`, а существующий
`example_app_runs` проходит через forwarding wrapper и вынесенную реализацию.

## Релизная матрица

- чистая Release-сборка с LibTooling: 11 из 11 тестов;
- чистая fallback-сборка без LibTooling: 10 из 10 тестов;
- `cmake --install` для обеих конфигураций успешен;
- оба установленных бинарника сообщают `CodeSplit 0.1.0`;
- `git diff --check` не обнаруживает дефектов.

## Публичный проект

Проверен [fmtlib/fmt](https://github.com/fmtlib/fmt), tag `11.2.0`, commit
`40626af88bd7df9a5fb80be7b25ac85b122d6c21`. Цель `fmt` собрана с экспортом compilation database.
В `src/os.cc` найдено 26 определений и 191 зависимость, frontend diagnostics отсутствуют.

План для `fmt::getpagesize` обнаружил прямой вызов `GetSystemInfo`, вернул blocker
`outgoing_dependency` и код 3. Целевой файл не создан. Это проверяет консервативный отказ на
реальном коде, а не только успешный искусственный пример.

## Границы MVP

- автоматически обрабатывается одна свободная non-inline и non-template функция с внешним
  связыванием, именованными параметрами и доказанным заголовком/target;
- variadic, deduced return type, rvalue-reference и другие недоказанные forwarding-сигнатуры
  блокируются как `delegation_unsupported`;
- известные исходящие call/type/global/macro dependencies пока блокируют преобразование;
- методы и классы присутствуют в inventory, но их делегирующее выделение относится к следующему
  этапу;
- затем обязателен разбор тел больших функций по CFG, data-flow, live-in/live-out, побочным
  эффектам, RAII и потоку управления;
- Tree-sitter для других языков и Docker требуют отдельных архитектурных решений после MVP.
