# ADR 0011: отделить план переноса от изменения исходников

- Статус: принято
- Дата: 2026-08-13

## Контекст

Семантический анализ уже предоставляет USR, диапазон определения, linkage и доказанные прямые
зависимости. Немедленное редактирование файлов смешало бы выбор допустимого преобразования,
построение текстовых замен и проверку результата. При неполном графе это затрудняет объяснение
отказа и повышает риск частичного изменения проекта.

## Решение

Ввести отдельную read-only команду `plan-move`. Она выбирает одну свободную функцию по USR и
возвращает либо упорядоченные будущие шаги, либо полный список блокирующих причин. Планирование
запрещается при недоступном inventory, несуществующем символе, совпадении исходного и целевого
пути, неподдерживаемом виде или linkage сущности, ограничениях callable, исходящих зависимостях,
macro dependency и входящих зависимостях без отдельного объявления.

Готовый план не содержит текстовых замен и не создаёт целевой файл. Статус `ready` означает только,
что текущие консервативные предусловия выполнены; он не является доказательством корректности ещё
не реализованного применения. Заблокированный план возвращает код завершения 3.

## Последствия

- решение объяснимо и одинаково представлено в text и JSON;
- имя функции не используется как идентификатор: перегрузки однозначно выбираются по USR;
- можно независимо тестировать политику допустимости и будущий механизм замен;
- первый полезный сценарий намеренно узок: только свободная функция с external linkage без
  исходящих и макрозависимостей;
- следующим этапом станет формирование непересекающихся замен в dry-run, всё ещё без записи файлов.
