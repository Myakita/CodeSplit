# ADR 0001: изолировать Clang LibTooling от ядра

- Статус: принято
- Дата: 2026-08-06

## Контекст

Для безопасной декомпозиции C/C++ недостаточно текстового анализа. Требуются препроцессинг,
разрешение имён, сведения о типах, точные диапазоны исходного кода и дальнейший анализ AST.
Результат зависит от настоящих флагов компиляции: стандарта языка, include-каталогов, макросов и
режима compiler driver.

## Решение

Использовать Clang LibTooling через отдельную библиотеку `codesplit_clang`. Публичный интерфейс
адаптера содержит только собственные модели CodeSplit и стандартные C++-типы. Реальная и fallback
реализации имеют одинаковый интерфейс и выбираются CMake на этапе сборки.

Базовый `analyze` продолжает работать без compilation database. Будущие операции, изменяющие
исходники, требуют успешного frontend-анализа.

## Рассмотренные альтернативы

### Собственный парсер C/C++

Отклонён из-за сложности шаблонов, макросов, расширений компиляторов, условной компиляции и
разрешения имён. Такой парсер стал бы отдельным компиляторным проектом и не обеспечил бы требуемую
надёжность.

### Запуск `clang.exe` как внешнего процесса

Подходит для проверки кода, но не предоставляет приложению структурированные объекты AST,
`SourceLocation` и данные препроцессора. Разбор текстовых диагностик нестабилен и зависит от версии
и локали.

### Обязательная зависимость всего ядра от LLVM

Отклонена, потому что подсчёт размера, CLI и форматирование отчётов не требуют многогигабайтного
development package. Изоляция уменьшает связанность и сохраняет проверяемую fallback-сборку.

### Ручной разбор `compile_commands.json`

Отклонён как дублирование `clang::tooling::CompilationDatabase`. LibTooling уже обрабатывает
поддерживаемые форматы базы и нормализацию команд compiler driver.

## Последствия

Положительные:

- ядро не зависит от нестабильного C++ API Clang;
- обновления LLVM локализованы в `src/clang` и CMake;
- можно тестировать конфигурации с LibTooling и без него;
- следующий AST-этап использует настоящие команды компиляции.

Ограничения:

- полный development-дистрибутив значительно увеличивает локальное окружение сборки;
- C++ API Clang может потребовать адаптации при обновлении версии;
- prebuilt LLVM на Windows может содержать платформенные настройки MSVC и DIA SDK;
- наличие compilation database не гарантирует наличие сгенерированных заголовков и успешный AST.
