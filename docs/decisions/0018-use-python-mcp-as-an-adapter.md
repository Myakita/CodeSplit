# ADR 0018: Использовать Python MCP-сервер как адаптер CodeSplit

## Статус

Принято для этапа после MVP 0.1.0.

## Контекст

CodeSplit должен быть доступен локальному агентскому ИИ компании. Модель полезна для понимания
запроса, смысловой группировки функций и методов, предложения структуры каталогов и нейминга. При
этом вероятностное решение модели не может заменять семантический анализ, транзакцию и проверку
сборки.

MCP можно реализовать внутри C++ CLI, отдельным Python-процессом либо как самостоятельную систему,
которая сама изменяет файлы. Встраивание протокола в C++ преждевременно связывает ядро с ещё одним
интеграционным SDK. Самостоятельная запись из Python дублирует критические правила безопасности.

## Решение

Реализовать MCP-сервер на Python как тонкий локальный адаптер:

- первый этап вызывает CodeSplit CLI с `--format json`;
- целевая архитектура использует стабильный CodeSplit Core API;
- Python не строит текстовые replacements и не изменяет исходники самостоятельно;
- первым транспортом используется `stdio`;
- read-only инструменты появляются раньше изменяющих;
- применение требует `plan_id`, совпадающих хешей и явного подтверждения;
- смысловые группы и имена являются предложением ИИ, которое валидирует CodeSplit.

CLI остаётся полноценным самостоятельным интерфейсом и не зависит от MCP.

## Последствия

Положительные:

- быстрая интеграция с локальным агентом и удобное тестирование протокольного слоя;
- зависимости MCP не проникают в C++-ядро;
- тяжёлый анализ остаётся в производительном C++/Clang-контуре;
- CLI и агент используют одинаковые правила безопасности;
- в дипломе явно разделяются вероятностное планирование и детерминированное доказательство
  применимости преобразования.

Ограничения:

- subprocess-вариант создаёт процесс на вызов и требует стабильного JSON-контракта;
- stdout MCP-процесса нельзя использовать для логов;
- версии Python и MCP SDK становятся отдельной частью поставки;
- перед корпоративной интеграцией нужно согласовать версию протокола, подтверждения, прогресс и
  разрешённые рабочие каталоги.

## Альтернативы

### MCP непосредственно в C++ CLI

Отклонено для первого этапа из-за лишнего протокольного сцепления и более высокой стоимости
разработки. Решение можно пересмотреть при появлении устойчивого требования к единому бинарнику.

### Python-сервер самостоятельно анализирует и меняет файлы

Отклонено: это создаёт вторую реализацию планировщика, транзакции и правил безопасности.

### Разрешить ИИ напрямую запускать произвольные команды CodeSplit

Отклонено: типизированные MCP-инструменты, планы с хешами и подтверждения дают более узкую и
проверяемую границу полномочий.
