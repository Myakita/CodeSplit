# ADR 0016: интегрировать новый файл только в доказанную CMake-цель

- Статус: принято
- Дата: 2026-08-13

## Контекст

Успешная компиляция нового `.cpp` отдельно не доказывает, что проект вообще собирает этот файл.
Обычный `cmake --build` также способен завершиться успешно, молча проигнорировав созданную единицу
трансляции.

## Решение

Для MVP поддерживается консервативный CMake-адаптер. `CMAKE_HOME_DIRECTORY` читается из
`CMakeCache.txt`, а имя цели извлекается из объектного пути `CMakeFiles/<target>.dir` настоящей
compilation command. Если обе связи не доказаны, dry-run блокируется.

В dry-run добавляется третья замена: полное проверяемое содержимое корневого `CMakeLists.txt`
дополняется отдельным `target_sources(<target> PRIVATE "<relative-path>")`. Apply транзакционно
обрабатывает исходник, новый файл и build file, затем запускает сборку только доказанной цели.

При неуспехе восстанавливаются все три файла. После файлового rollback CMake повторно
конфигурируется из восстановленного проекта, чтобы убрать временную цель из производного build
graph.

## Последствия

- успешный результат доказывает, что новый файл действительно компилировался в составе цели;
- изменение `CMakeLists.txt` защищено тем же сравнением ожидаемого текста от устаревшего dry-run;
- поддерживается только CMake-проект с доступным cache и распознаваемым объектным путём;
- существующие команды не переписываются: добавляется независимый декларативный `target_sources`;
- выбор конфигурации multi-config generator и запуск тестов остаются последующей работой;
- другие build systems потребуют собственных адаптеров с тем же интерфейсом доказательств.
