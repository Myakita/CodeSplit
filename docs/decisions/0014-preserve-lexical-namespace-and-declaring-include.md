# ADR 0014: сохранять лексический namespace и declaring include

- Статус: принято
- Дата: 2026-08-13

## Контекст

Текст определения функции недостаточен для самостоятельного нового `.cpp`. Определение внутри
namespace потеряет семантическое имя без обёртки, а сигнатура и объявление могут зависеть от
заголовка исходного файла.

## Решение

Inventory сохраняет цепочку именованных лексических namespace функции. План дополнительно ищет
прямой `#include`, разрешённый путь которого совпадает с файлом канонического объявления. Dry-run
добавляет этот include и воспроизводит namespace-обёртки в новом файле. Anonymous namespace уже
исключается правилом external linkage.

Используется именно lexical, а не semantic declaration context. Определение вида
`int company::function()` вне namespace уже содержит квалификацию в своём тексте и не должно быть
повторно обёрнуто. Если объявление находится в другом файле, но соответствующий прямой include не
доказан, план блокируется как `declaration_include_unavailable`.

## Последствия

- новый файл сохраняет квалифицированную идентичность функции;
- declaring header даёт сигнатуру, нужные типы и объявления без угадывания набора include;
- транзитивно доступное объявление пока не превращается автоматически в прямой include;
- минимизация include и выбор forward declaration остаются отдельной оптимизацией;
- C и функции глобального namespace продолжают использовать пустую цепочку namespace.
