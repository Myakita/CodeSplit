# ADR 0017: сохранять исходный entry point через делегирование

## Контекст

Перенос целого определения в новый `.cpp` сохраняет линковку при наличии декларации, но может
оставить исходный файл пустой оболочкой и не выражает декомпозицию в самом коде. Требование проекта
состоит в том, чтобы прежняя функция, метод или фасад класса продолжали быть точкой входа, а
вынесенная часть вызывалась с исходного места.

## Решение

Для свободной функции MVP сохраняет имя, сигнатуру и расположение исходного определения. Её тело
заменяется вызовом детерминированно названной implementation-функции. Прежнее тело переносится в
новый `.cpp`, который включается в ту же CMake-цель. Для возвращающей функции wrapper использует
`return`, для `void` — обычный вызов.

Inventory хранит точные позиции имени и тела, имена параметров и категорию результата. Безымянные
параметры, variadic, templates, inline-функции, deduced return type и rvalue-reference параметры
пока получают структурированное ограничение `delegation_unsupported`.

## Последствия

- существующие вызовы и тесты продолжают использовать прежний API;
- новый тест на ту же бизнес-логику не генерируется;
- сборка проверяет и wrapper, и вынесенную реализацию;
- в бинарнике появляется отдельный implementation-символ;
- методы и классы должны использовать тот же принцип совместимости, но требуют отдельной модели
  `this`, состояния объекта, владения и заголовков;
- декомпозиция части тела большой функции остаётся следующим исследовательским уровнем с CFG и
  data-flow, а не произвольным вырезанием строк.
