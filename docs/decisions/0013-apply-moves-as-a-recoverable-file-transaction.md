# ADR 0013: применять перенос как восстанавливаемую файловую транзакцию

- Статус: принято
- Дата: 2026-08-13

## Контекст

Dry-run уже формирует две проверенные замены, но последовательная запись сначала исходника, затем
цели может оставить проект в частично изменённом состоянии. Между dry-run и применением исходник
также может измениться внешним процессом.

## Решение

Ввести отдельную команду `apply-move`, требующую явный флаг `--confirm`. Dry-run сохраняет ожидаемый
текст удаляемого диапазона, а apply повторно читает исходник и сравнивает его перед записью.

Новые версии обоих файлов сначала полностью записываются в соседние `.codesplit.tmp`. Исходник
переименовывается в `.codesplit.bak`, после чего staged-файлы вводятся в рабочие имена. При ошибке
commit новый исходник удаляется, backup возвращается на место, а staged-файлы очищаются. После
успеха backup удаляется; невозможность удалить его выдаётся как предупреждение без ложного
утверждения, что применение не состоялось.

## Последствия

- неподтверждённая команда завершается до анализа и записи;
- изменение исходного диапазона или появление цели после dry-run блокирует применение;
- сбой файлового commit приводит к попытке автоматического отката и отдельному признаку результата;
- это транзакционное поведение уровня файлов, а не одна атомарная операция файловой системы;
- автоматические frontend-анализ, сборка и тесты после commit пока не входят в транзакцию и будут
  следующим этапом.
