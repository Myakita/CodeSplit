# ADR 0008: сохранять прямые include-зависимости с исходным происхождением

- Статус: принято
- Дата: 2026-08-13

## Контекст

План переноса сущности должен понимать, какие заголовки непосредственно подключены исходным
файлом. AST содержит результат препроцессинга, но не представляет директиву `#include` обычным
узлом дерева. Один разрешённый заголовок также может быть подключён разными написаниями и из разных
мест, а транзитивная зависимость не эквивалентна прямой директиве в основном файле.

## Решение

Clang-адаптер устанавливает `PPCallbacks` и обрабатывает `InclusionDirective`. В текущем срезе
сохраняются только директивы, у которых `#` написан в основном анализируемом файле. Для каждой
директивы `IncludeDependency` содержит:

- вид `quoted` или `angled`;
- имя заголовка в том виде, в котором оно записано между разделителями;
- путь к файлу, разрешённый препроцессором с настоящей командой компиляции;
- `SourceRange` от `#` до конца имени заголовка в исходном файле.

Отдельные директивы не дедуплицируются по целевому пути: их исходное происхождение является частью
модели. При ошибке frontend include-зависимости очищаются вместе с частичным AST inventory.

## Рассмотренные альтернативы

### Восстанавливать заголовки по местоположению AST-деклараций

Отклонено: это показывает файл определения сущности, но не доказывает, какая директива и по какой
цепочке сделала декларацию доступной.

### Сохранять все транзитивно открытые заголовки как равноправные рёбра

Отклонено для первого среза: теряется различие между прямой директивой и следствием чужого
заголовка. Транзитивное замыкание можно построить позже как отдельное представление графа.

### Дедуплицировать директивы по разрешённому пути

Отклонено: повторное подключение, условная компиляция и разные места директив являются фактами
исходного текста, которые потребуются при планировании изменений.

## Последствия

Положительные:

- прямые и транзитивные подключения не смешиваются;
- сохраняются одновременно написанное имя и фактическая цель поиска заголовка;
- origin позволяет показать пользователю точное место будущего изменения;
- модель не экспортирует типы препроцессора Clang за границу адаптера.

Ограничения:

- пока не строится граф включений между всеми заголовками;
- условие препроцессора, внутри которого находится директива, не сохраняется;
- `#include_next`, import и C++ modules ещё не имеют отдельной семантики;
- наличие прямой директивы само по себе не доказывает, что она нужна конкретной callable.
