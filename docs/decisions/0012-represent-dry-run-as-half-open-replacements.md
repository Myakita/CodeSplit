# ADR 0012: представить dry-run набором половинно-открытых замен

- Статус: принято
- Дата: 2026-08-13

## Контекст

Готовый `MovePlan` описывает допустимость и порядок действий, но намеренно не содержит текста
изменений. Перед реализацией записи нужен проверяемый промежуточный результат, который однозначно
показывает, какие байты были бы удалены и добавлены.

## Решение

Ввести отдельную команду `dry-run-move` и модель `MoveDryRun`. Каждая замена содержит путь,
половинно-открытый диапазон байтов `[begin_offset, end_offset)` и новый текст. Для первого среза
формируются ровно две замены: удаление определения из исходника и вставка его точного текста в
позицию 0 нового целевого файла.

Dry-run блокируется, если исходный план заблокирован, исходник нельзя прочитать, диапазон выходит
за размер файла, целевой файл уже существует или замены пересекаются. Стиль перевода строк
исходника сохраняется. Команда только сериализует замены и возвращает код 3 при блокировке; файлы
не создаются и не изменяются.

## Последствия

- касающиеся границами диапазоны не считаются пересечением;
- вставки в одну позицию одного файла конфликтуют;
- JSON содержит точный `replacement_text`, поэтому результат пригоден для внешней проверки;
- существующий целевой файл пока не дополняется: для него потребуется отдельная политика include,
  namespace и порядка деклараций;
- следующий этап может атомарно применить уже проверенный набор замен и затем валидировать проект.
