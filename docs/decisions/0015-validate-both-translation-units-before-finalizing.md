# ADR 0015: валидировать обе единицы трансляции до завершения commit

- Статус: принято
- Дата: 2026-08-13

## Контекст

Даже готовый план опирается на намеренно неполный граф зависимостей. Например, локальный type alias
может быть частью текста сигнатуры, но не попасть в текущую модель type references. После файлового
переноса исходник способен остаться корректным, а новый `.cpp` — не разбираться.

## Решение

Backup исходника сохраняется до повторного frontend-анализа обоих получившихся файлов. Исходная
compilation command адаптируется к новому пути заменой аргумента единицы трансляции; стандарт языка,
include paths, defines и режим compiler driver сохраняются.

Если исходник или цель возвращает frontend failure, новый исходник и цель удаляются, backup
возвращается на исходный путь. Результат содержит `validated`, `rolled_back` и blocker
`validation_failed`; первая error/fatal diagnostic включается в объяснение.

## Последствия

- успешный `apply-move` теперь означает синтаксическую и семантическую приемлемость обоих файлов для
  Clang frontend;
- validation защищает от пропущенного класса зависимостей, но не заменяет расширение графа;
- переиспользуется реальная команда проекта, а не фиксированный стандарт CodeSplit;
- линковка, включение нового файла в build target и тесты ещё не проверяются;
- следующая граница MVP — интеграция нового файла в систему сборки и проверка затронутой цели.
