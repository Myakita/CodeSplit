# ADR 0003: связывать декларации по канонической идентичности

- Статус: принято
- Дата: 2026-08-07

## Контекст

Квалифицированного имени недостаточно для связи определения с объявлением. Перегруженные методы
могут иметь одинаковое имя и отличаться типами параметров, cv-квалификаторами и ref-квалификаторами.
Указатель на декларацию Clang однозначен только во время обработки одной единицы трансляции и не
может входить в публичную модель CodeSplit.

## Решение

Внутри AST каноническая декларация Clang является источником истины для связи redeclaration chain.
Для переносимой идентичности CodeSplit генерирует USR канонической декларации и сохраняет его в
собственном строковом поле `symbol_id`.

Если каноническая декларация отличается от определения, CodeSplit сохраняет её исходный диапазон.
Для метода также сохраняется диапазон класса-владельца. Публичный `SourceRange` содержит только путь,
байтовые смещения и строки; типы и указатели Clang остаются внутри `src/clang`.

Если USR получить невозможно, CodeSplit не подменяет идентичность сравнением имён. Текущий
диагностический `analyze` может вернуть пустой идентификатор, но будущая изменяющая операция должна
считать такую сущность неразрешённой до появления доказуемой идентичности.

## Рассмотренные альтернативы

### Квалифицированное имя

Отклонено: оно не различает перегрузки и не кодирует полную сигнатуру.

### Указатель на canonical declaration в публичной модели

Отклонён: его время жизни ограничено AST, значение нестабильно между запусками и нарушает границу
между `codesplit_clang` и ядром.

### Собственная сериализация сигнатуры

Отложена: корректная обработка шаблонов, typedef, dependent types и расширений языка дублировала бы
часть семантики Clang. Она может понадобиться только как явно версионированная альтернатива USR.

## Последствия

Положительные:

- перегрузки связываются по семантической сущности, а не по имени;
- отчёт содержит идентификатор и точные диапазоны связанных деклараций;
- будущий граф зависимостей не зависит от времени жизни AST;
- публичная модель по-прежнему использует только стандартные типы C++.

Ограничения:

- формат USR определяется Clang и может потребовать миграции при обновлении LLVM;
- не для каждой декларации гарантирована генерация USR;
- текущая связь строится в пределах одной обработанной единицы трансляции.
