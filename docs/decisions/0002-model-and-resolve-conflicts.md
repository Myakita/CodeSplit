# ADR 0002: моделировать ограничения и разрешать конфликты доказуемо

- Статус: принято
- Дата: 2026-08-06

## Контекст

Перенос объявления, определения или части функции может встретить несколько независимых проблем:
макросы, коллизии имён, внутреннее связывание, include-циклы, недоступный исходный диапазон,
изменение времени жизни объектов и сложный поток управления. Один флаг `safe` не объясняет
причину и не позволяет выбрать способ исправления.

## Решение

CodeSplit накапливает структурированные ограничения для каждой анализируемой сущности. Каждое
ограничение содержит тип, расположение, объяснение и в дальнейшем список допустимых способов
разрешения. Планировщик назначает результату один из трёх статусов:

- `resolved_automatically` — существует детерминированное преобразование, прошедшее все проверки;
- `needs_confirmation` — безопасны несколько вариантов или решение меняет публичную структуру;
- `blocked` — доказательства сохранения семантики недостаточны.

Автоматическое разрешение не означает игнорирование конфликта. Ограничение считается снятым только
после построения непересекающихся replacement, повторного frontend-анализа и доступной проверки
сборки.

Текущая модель `CallableConstraint` является первым минимальным воплощением решения. Она различает
происхождение из макроса, отсутствие надёжного исходного диапазона и случай, когда функция сама
превышает лимит.

## Предполагаемые стратегии

| Конфликт | Возможное разрешение | Начальная политика |
|---|---|---|
| Недостающий include | Добавить include, подтверждённый используемой декларацией | Автоматически |
| Include-цикл | Заменить допустимую зависимость на forward declaration | Автоматически после проверки |
| Зависимость с internal linkage | Перенести замкнутый кластер или оставить реализацию рядом | Подтверждение |
| Коллизия имени или целевого файла | Выбрать другое имя из предложенного плана | Подтверждение |
| Определение создано макросом | Не переносить как обычный текст | Блокировка |
| Функция больше лимита | Запустить поиск области для extract function | Отдельный анализ |
| `goto`, внешний `break`/`continue`, сложный `return` | Построить явный протокол результата либо отказаться | Блокировка до доказательства |
| Изменение границ RAII | Сохранить scope или отказаться от кандидата | Блокировка до доказательства |

Таблица задаёт исходную политику, а не гарантирует, что каждый перечисленный конфликт уже
реализован.

## Последствия

Положительные:

- отчёт объясняет, почему преобразование возможно или запрещено;
- несколько проблем одной сущности не маскируют друг друга;
- алгоритмы разрешения добавляются независимо;
- диплом можно оценивать по доле доказуемо разрешённых классов конфликтов.

Ограничения:

- требуется стабильная модель идентичности сущностей и исходных диапазонов;
- подтверждение безопасности дороже простого текстового переноса;
- часть конфликтов принципиально останется интерактивной или заблокированной.
